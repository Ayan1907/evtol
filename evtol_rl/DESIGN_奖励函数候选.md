## 候选 A · 势函数 Shaping（推荐第一版，先跑通）

**思想**：只用"离目标 3D 距离的缩短量"做逐步奖励，终端给到达/碰撞大额项。

```
r_t = k_shape × (d_{t-1} − d_t)          # 3D 欧氏距离，k_shape≈1.0~2.0
r_t += R_ARRIVE(=100)   若 arrived
r_t += R_COLLIDE(=−100) 若 collision / height_violation
r_t += R_STEP(=−0.01)   每步
```

**为什么先做它**：
1. **势函数 shaping（Ng et al. 1999）保证不改变最优策略**——γ·Φ(s')−Φ(s) 形式，理论上无偏。这是面试时"shaping 是否引入策略偏差"的标准答案。
2. 已知 naive 策略的失败模式是"卡在 155m 不下降"。距离项天然鼓励下降（下降缩短 3D 距离），所以**第一版就大概率能学到进近下降**。
3. 项数少，出问题时容易定位是环境问题还是奖励问题。

**预期坑**：距离最短路径可能穿楼 → 碰撞惩罚要足够大（撞楼 = 损失剩余全部 progress + 额外罚），否则策略会赌"贴楼抄近路"。

## 候选 B · 能耗 + 安全裕度版（你的差异化核心，第二版）

在 A 基础上加两项，这是"把物理约束嵌进 RL 环境"、和"跑 CartPole 的人"拉开差距的地方：

```
r_t = A的各项
    − w_energy × E_step_kwh / E_ref      # 单步能耗（step_power 已给 E_j）
    − w_margin × margin_deficit          # 安全裕度项
```

- **能耗项**：`E_step` 来自 `info["energy_j"]`。归一化参考：巡航 50 m/s、stride 25m、dt=0.5s，单步约 0.015–0.020 kWh。建议 `w_energy` 使能耗项 ≈ progress 项的 10–30%——太小学不到节油，太大策略会爬到省电高度磨蹭（时间惩罚要能镇住）。
- **安全裕度项**：高度带是"合规"底线，但**贴边飞（离 min_h/max_h 只差几米）不是好策略**。设计一个"离允许带边界 < 20m 就按米数扣分"的项（`env.allowed_height_range()` 与 `env.height_violation()` 都是现成接口，violation=0 但 margin 小的情况要自己算）。**这一项占位注释里明确写了是你的设计空间。**

**为什么值得做**：TEeVTOL (Liu et al., 2024) 被原项目综述点名的缺口就是"纯 RL 缺安全裕度和规范约束"。你的奖励函数里出现"安全裕度"四个字，文献故事就闭环了。

**预期坑**：能耗项会让策略倾向"低空慢飞"（空气密度大、旋翼效率变化），可能和风场项打架——所以**风场项建议第三版再开**。

## 候选 C · 对齐原项目 5 目标评估器（终版，最重）

原项目 `PathEvaluator` 的 5 目标 = [energy, time, noise, safety, length]，权重 0.25/0.20/0.20/0.20/0.15。把单步奖励做成同一目标的逐步近似（能耗用 step_power、噪声用 ImprovedNoiseModel、安全用 clearance/constraint cost），评估时用同一个 `PathEvaluator.evaluate(path)` 打分——**"同一把尺子量 RL 和 A*/NSGA-II"**，这是 baseline_compare 最有说服力的口径。

**风险**：项多、量纲乱、reward hacking 空间大（比如噪声项可能鼓励飞无人区）。只在 A/B 已稳定通关后再开。

## 填写时的四条工程纪律

1. **每步 |r| 保持在 O(0.1–10) 量级**，终端项 O(100)。progress 项每步 ≈1（25m/25m×1.0）是合理锚点。
2. **一次只改一项**，跑 1e5 步看曲线再决定下一项——否则你讲不出"哪一项起了作用"。
3. **奖励项全部写成类常量**（R_* / W_*），别写魔法数字进函数体，config.py 是唯一调参入口。
4. **先 W_ENERGY=0 跑通 A，再开能耗**（占位注释也是这么建议的）。

## 附：奖励维度分析（2026-10-27，回答"奖励为什么不必五维"）

### time 与 length 在本环境中完全线性等价

- 环境恒速：`dt = stride/cruise_speed = 25/50 = 0.5s`（常数，不建模加减速）
- `总时间 = 步数 × 0.5s`，`路径长度 ≈ 步数 × 25m` → **时间 = 长度 ÷ 50，逐点线性等价**
- 原项目 PathEvaluator 5 维中 time(0.20)+length(0.15)=0.35 权重实际压在同一目标上

### 评估函数 ≠ 奖励函数

| | 评估（PathEvaluator） | 奖励（_compute_reward） |
|---|---|---|
| 用途 | 离线打分，与 A*/NSGA-II 同尺对比 | 在线学习信号 |
| 维度 | 5 维（对外口径） | 环境可分辨的独立维度数 |

### 推荐形态：3+1 维

```
r_t = k × (d_{t-1} − d_t)          ← 进度（time/length 合并项）
    − w_e × (E_step / E_ref)       ← 能耗，E_ref = 巡航单步能耗（归一化）
    − 2.0 × 高度越带米数            ← 合规（已实现，第④项）
    − w_m × 裕度亏空                ← 安全裕度（设计空间：离允许带边界 <20m 按米扣）
    − 0.01                          ← 步数惩罚（防磨蹭）
    + 100 到达 / −100 撞楼·违规
```

- ①③ 的张力（直线快但穿楼耗能 vs 绕行慢但省）= 策略要学的多目标权衡
- 噪声项第三版再开（`calculate_noise_level` 接口现成，需传 map 对象）
- 想要第 5 个独立维度的正道 = 动作改加速度控制（速度可变），工程量大，记入未来工作

### 面试讲法

"评估用 5 维保持与 NSGA-II 同尺可比；奖励只含环境动力学可分辨的独立维度——
恒速假设下 time 与 length 线性等价，合并进步度项。奖励维度是设计决策，
不是评估维度的照抄。"
